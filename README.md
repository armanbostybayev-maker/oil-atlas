# Oil Atlas — мировой GIS-dashboard

Отдельное приложение внутри существующего проекта `oil`. Главный экран — интерактивная карта мира: 258 стран/территорий, 658 исходных записей НПЗ, аналитическая заливка стран, пропорциональные символы, фильтры и компактные карточки. Данные не генерируются случайно и не запрашиваются из внешней аналитической базы.

## Запуск

### Язык, размеры и справка

Переключатель **English / Русский** находится справа вверху. Язык интерфейса сохраняется в браузере после перезагрузки; переключение не сбрасывает карту, фильтры и выбранный режим. Переведены панели, режимы, показатели, единицы, сообщения и подсказки. Подписи стран на карте по-прежнему используют `NAME_EN`, а имена владельцев и исходные атрибуты сохраняются как в источнике.

Размеры меню и плашек увеличены на **30%**, текст интерфейса — на **60%** относительно исходной версии; на узком экране ширина ограничивается viewport, а длинные панели прокручиваются. Размеры географических объектов и подписи карты не масштабируются вместе с интерфейсом.

В бургер-меню у каждого из 13 режимов есть кнопка **ⓘ**. Она открывает окно «Что показывает / Как рассчитывается / Ограничения данных», не переключая режим. Окно закрывается крестиком, кликом вне окна или Escape; фокус возвращается на исходную кнопку. Объяснения доступны на обоих языках.

Локализация: `controls/i18n.jsx`, `controls/ru.mjs`, `controls/LanguageSwitcher.jsx`. Описания: `analytics/descriptions.mjs`, `panels/ModeHelp.jsx`. Проверка этих сценариев: `npm.cmd run test:browser -- --interface` при работающем dev-сервере.

Из корня `oil`:

```powershell
npm.cmd --prefix "oil stat" run dev
```

Открыть **http://127.0.0.1:5180/**. Подготовка данных выполняется автоматически перед запуском; ручной обработки не требуется. При неизменных исходниках используется SHA-256 cache.

Приложение переиспользует установленные пакеты из `../frontend/node_modules`. Исходный frontend и backend не изменены. Если пакеты ещё не установлены, выполнить `npm.cmd install --prefix frontend` согласно существующему проекту. Для отдельной установки можно выполнить `npm.cmd install` внутри `oil stat`: локальные пакеты имеют приоритет. Нужен Node.js, совместимый с Vite 7 (20.19+ или 22.12+; проверено на Node 24).

```powershell
npm.cmd --prefix "oil stat" run build
npm.cmd --prefix "oil stat" run preview
npm.cmd --prefix "oil stat" test
npm.cmd --prefix "oil stat" run test:browser
```

`preview` обслуживает production-сборку на порту 5180: перед запуском остановить dev-сервер либо передать `-- --port 5181`. Браузерный тест запускается при работающем dev-сервере и использует установленный Microsoft Edge через Playwright. Результаты и PNG сохраняются в `artifacts/`. Сервер не требует FastAPI, Postgres, Docker или секретного API-ключа для базовой локальной карты.

## Стек и структура

React 19 + Vite 7 + MapLibre GL JS 6.9, ES modules/JSX; модели описаны в `types/models.d.ts`. Это тот же картографический и UI-стек, что у существующего frontend. Собственная светлая тема изолирована от тёмных стилей геологического приложения. Нет новых runtime-зависимостей. Отдельный MapLibre worker собирается Vite через `?worker&url`; это необходимо для MapLibre 6.9 и проверено в dev и build.

```text
oil stat/
  main.jsx                    загрузка данных, error boundary
  components/AtlasApp.jsx      связанное состояние интерфейса
  map/                        MapLibre, GeoJSON-слои, подложки, цветовые шкалы
  controls/                   поиск и проверяемое URL-состояние
  panels/                     страны, НПЗ, сравнение, владельцы, качество
  analytics/                  переиспользуемые расчёты и правила режимов
  data/                       preprocessing, нормализация, spatial join
  utils/                      числа, missing data, статистические функции
  types/                      модели исходных объектов
  styles/                     изолированная адаптивная тема
  public/data/                автоматически подготовленные данные/диагностика
  scripts/run.mjs             запуск с существующими или локальными пакетами
  tests/                      расчёты, пространственная логика, browser checks
  dist/                       production build (не входит в git)
```

Предрасчёт spatial join выполняется один раз в Node.js. Полная геометрия используется для присвоения страны; MapLibre упрощает её только для отрисовки. Агрегации, фильтрованные наборы и статистики мемоизированы. НПЗ рисуются одним WebGL circle-layer без сотен DOM-маркеров. Подписи `NAME_EN` создаются локально как спрайты с автоматическим подавлением перекрытий: удалённый font/glyph server не нужен.

## Источники и фактическая схема

Четыре файла из `../refinery/geojson/`:

- `country world.geojsonl`: 258 полигональных объектов WGS84, `NAME_EN`, `NAME_RU`, значения/годы добычи, потребления, ВВП, структуры продуктов, поля цен и источников.
- `refinary world.geojsonl`: 658 точек WGS84 с именами, координатами, владельцами, мощностью, статусом, возрастом, сырьём, происхождением нефти, продукцией и URL.
- `country world.qmd`: метаданные QGIS, CRS EPSG:4326. Числовой статистики не содержит. Записанный extent — пустое служебное значение, не используется для карты.
- `refinary world.qmd`: метаданные QGIS с незаполненным CRS/extent. Геометрии точек в GeoJSONL уже заданы lon/lat; `xcoord/ycoord` — другие, метрические координаты и не подменяют GeoJSON geometry.

Все реальные имена аналитических полей явно перечислены в `data/normalize.mjs` (`FIELDS`, `YEAR_FIELDS`). Исходные атрибуты сохранены в `raw` и доступны в раскрываемом блоке каждой карточки. Ссылки открываются как внешние HTTP(S)-источники; текст не выполняется как HTML или инструкции.

### Нормализация

- Числовой parser принимает только полностью числовые строки: убирает обычные/неразрывные пробелы, приводит десятичную запятую к точке, поддерживает `%`. Не извлекает случайное число из описательного текста.
- Приоритет мощности: `Переработка, т/год (пересчитано)` → строго числовое `Мощность переработки, т/год` → `Переработка, млн т/год × 10⁶`. Описания вида «около … барр./сут.» не интерпретируются повторно, если структурированной мощности нет.
- Пустое, `null`, неизвестное и нечисловое значение становятся `null` для расчётов; исходный текст остаётся доступен. Настоящий числовой 0 сохраняется. Отрицательная мощность не принимается.
- Статус берётся из краткого поля `Статус`: действующий → Active, закрыт → Closed, модернизация → Modernization, неизвестно → Unknown. Нераспознанный `перформативан` также Unknown. Подробное поле `Статус на 2026 г.` не затирается; конфликты отмечаются.
- Возраст принимается только из явно указанного числа лет в начале поля; приблизительный возраст, возраст юрлица/предшественника и неподтверждённый год не используются. Для закрытых НПЗ это зафиксированный срок эксплуатации до закрытия; для действующих — сообщённый возраст на 2026 год. Средние считаются только по известным возрастам, с указанием покрытия в tooltip.
- Владельцы: Unicode NFKC, нормализация пробелов, небольшой явный список алиасов BP/Ampol/ExxonMobil/Viva. Описательные заглушки вроде «Текущий владелец/оператор указан в официальном перечне PAJ» считаются неизвестными, а не компаниями. Совместные предприятия остаются исходными группами: доли владения не выдумываются.

### Spatial join

1. Проверка координат: конечные lon/lat в диапазонах ±180/±90.
2. Bounding-box индекс отдельных Polygon-компонентов, затем point-in-polygon с учётом holes и MultiPolygon.
3. Единственное попадание определяет страну. Несколько попаданий — ambiguous, страна не назначается.
4. Для точки вне полигонов: ближайшая граница в пределах **5 км**. Расстояния считаются в локальной проекции с поправкой `cos(latitude)`, приемлемой на таком радиусе. Если второй кандидат ближе чем best + **1 км**, присвоение отклоняется.
5. В списке fallback сохраняются метод и расстояние, в unmatched — причина и кандидаты.

Итог: **605 точных попаданий + 52 coastal fallback = 657 matched; 1 unmatched**. Неприсвоенный объект — запись 160, **Okinawa Sekiyu Seisei / Yonashiro record**, `[127.9628277, 26.3511134]`: вне допустимого расстояния от предоставленных полигонов. Он остаётся на карте и в общем числе записей, но не входит в статистику страны. Текст страны для назначения не использовался. Очень малые острова/качество береговой линии могут влиять на результат; территориальная принадлежность следует исходным полигонам.

## Аналитические режимы

| Режим                   | Что меняется на карте                                                                  |
| ----------------------- | -------------------------------------------------------------------------------------- |
| Overview                | Нейтральные страны, все НПЗ, sqrt-size по мощности                                     |
| Oil Balance             | Типология или Production/Consumption, Refining/Consumption                             |
| Refining Capacity       | Сумма известных мощностей, число, средняя, медиана, максимум                           |
| Production              | Total liquids, Crude Oil, NGPL, bbl/day                                                |
| Consumption             | Потребление, на запись НПЗ, Consumption/Capacity                                       |
| Refinery Infrastructure | Число, размеры, доля крупнейшего, HHI                                                  |
| Refinery Age            | Средний/медианный известный срок эксплуатации, >30/>50/>70                             |
| Refinery Status         | Число, доля и мощность выбранного статуса; фильтр точек                                |
| Product Mix             | Diesel, Gasoline, LPG, Jet/Kerosene, Residual Fuel Oil, %                              |
| Economics               | GDP, рост, CPI, нефтяные интенсивности                                                 |
| Fuel Prices             | Пять продуктов; сравнение только внутри одинаковой исходной единицы и при наличии даты |
| Owners                  | След выбранного владельца, мощность/число НПЗ по странам                               |
| Anomalies               | Девять прозрачных категорий, остальные страны не выделены и их точки скрыты            |

Кнопка «Все компании» справа вверху раскрывает **полный список владельцев из данных**, отсортированный по сумме известных записанных мощностей. Внутри есть поиск; длинный список прокручивается. Hover выделяет точки, выбор включает один owner-filter, подбирает extent и закрывает список; Clear возвращает точки. Список закрывается повторным нажатием кнопки, Escape или кликом вне панели. Для выбранной компании показаны число записей, страны, крупнейшая запись и покрытие. Это не рейтинг собственников по equity-adjusted capacity и не подтверждённая текущая производственная мощность.

Легенда прижата к левому краю. При открытом бургер-меню его доступная высота вычисляется по фактическому положению легенды; режимы прокручиваются над ней, не закрывая шкалу, в том числе после смены показателя или размера окна.

Поиск поддерживает английские/русские названия стран, названия НПЗ и владельцев; стрелки/Enter/Escape. Клик по карте или результату поиска открывает карточку. Compare позволяет выбрать вторую страну списком или кликом. Карточки прокручиваются, карта остаётся видимой. Основные параметры `mode`, `metric`, `country`, `owner`, `status`, `basemap`, `anomaly`, `priceUnit` сохраняются в URL; неверные значения режимов проверяются. Reset View сбрасывает выбор и фильтры, возвращает мировой масштаб и сохраняет подложку.

Числовые заливки используют quintile-классы (20/40/60/80 percentiles), фактические границы видны в легенде. Для отрицательного и положительного GDP growth/CPI — diverging colors. Missing — отдельный серый цвет. Изменение показателя меняет заливку непосредственно на карте. Owner/status фильтры меняют точки и KPI; национальные production/consumption/GDP остаются национальными показателями. В Owners и Status изменяется также агрегация заливки.

## Формулы и ограничения

Обозначения: `Cᵢ` — известная мощность записи НПЗ в т/год; `P` — total liquids bbl/day; `D` — consumption bbl/day; `G` — GDP в **млрд USD**; `N` — число сопоставленных записей НПЗ страны.

| Показатель                         | Формула                                                        |
| ---------------------------------- | -------------------------------------------------------------- |
| Записанная мощность                | `Σ known Cᵢ / 10⁶`, Mt/year; null, если нет известных значений |
| Приблизительная мощность bbl/day   | `Σ Cᵢ × 7.33 / 365`                                            |
| Production / Consumption           | `P / D`                                                        |
| Refining / Consumption             | `(Σ Cᵢ × 7.33 / 365) / D`                                      |
| Consumption / Refining             | `D / (Σ Cᵢ × 7.33 / 365)`                                      |
| Consumption per refinery           | `D / N`                                                        |
| Средняя мощность                   | `Σ Cᵢ / N`                                                     |
| Медиана / максимум                 | Median / max списка мощностей                                  |
| Доля крупнейшего                   | `max(Cᵢ) / Σ Cᵢ × 100%`                                        |
| HHI                                | `Σ(Cᵢ / Σ Cᵢ)² × 10,000`                                       |
| Доля статуса                       | `N_status / N × 100%`                                          |
| Refining intensity                 | `Σ Cᵢ / G`, t/year на миллиард USD                             |
| Consumption / Production intensity | `D / G`, `P / G`, bbl/day на миллиард USD                      |

**7.33 барреля/тонну — приблизительный коэффициент, а не точное физическое равенство:** плотность нефти различается. 365 — фиксированная аналитическая база дней/год. Некоторые исходные мощности уже являются пересчитанными; первичный текст сохранён. Мощность не равна фактической переработке, выпуску продуктов или экспорту.

Нулевой/неизвестный знаменатель → `No data`. При неполных мощностях или подозрении на дубли общая записанная сумма доступна с оговоркой, но средняя/медиана/максимум как национальные показатели, HHI, доля крупнейшего, refining ratios/intensity не публикуются. Страна без найденных НПЗ имеет `count=0`, но `capacity=null`: это не доказательство отсутствия отрасли.

**Годы не синхронизированы.** В карточках и tooltip указаны годы каждого показателя; в смешанных отношениях указаны оба года. Например, добыча 2025 и потребление 2024 не выдаются за баланс 2025. Типология и аномалии — исследовательские сигналы на этих срезах, не торговый баланс одного года. Статус — 2026; мощность может быть исторической. Включены закрытые объекты.

### Типология — `analytics/config.mjs`

Правила выполняются по порядку при доступных `P/D`, `R/D` и полном проверяемом покрытии мощности:

1. Raw Oil Exporter: `P/D ≥ 1.5`, `R/D < 1`.
2. Refining Hub: `R/D ≥ 1.25`.
3. Import Dependent: оба отношения `< 0.5`.
4. Large Consumer Market: потребление ≥ 75-го перцентиля известных стран.
5. Balanced Market: оба отношения в `[0.8, 1.2]`.
6. Иначе Insufficient Data (включая неклассифицированные пограничные случаи).

### Аномалии — `analytics/atlas.mjs`

- High Production + Low Refining: production ≥ P75, refining bpd < 0.5 × production.
- High Refining + Low Domestic Consumption / Large Refining Surplus: R/D > 1.5.
- High Consumption + Low Refining: consumption ≥ P75 и R/D < 0.5.
- Many Small Refineries: count ≥ P75 положительных counts, average capacity < P25.
- Few Very Large Refineries: 1–3 записи и average capacity ≥ P75.
- High Closed Capacity Share: доля закрытой мощности >25%, полные мощности.
- Old Active Refinery Fleet: средний известный возраст >50, минимум 3 возраста, покрытие активного парка ≥70%.
- Large Refining Deficit: R/D <0.5.

Surplus/deficit — относительно мощности, не измеренные экспорт/импорт. Две surplus-категории имеют один порог намеренно; они представляют один сигнал в разных формулировках задания.

### Похожие страны

Production, Consumption, Capacity, Count и пять долей продуктов стандартизуются по среднему/стандартному отклонению известных значений. Расстояние — `sqrt(mean(((xᵢ − yᵢ)/σᵢ)²))` по общим признакам, минимум 6 из 9, σ>0. Возвращается до 5 ближайших, показаны расстояние и число общих признаков. При недостатке данных список отсутствует. Различающиеся наборы признаков/годы ограничивают сопоставимость; это exploratory similarity.

API слоя: `getCountryRefineries`, `getCountryRefiningCapacity`, `getCountryOilBalance`, `getOwnerStatistics`, `getRefineryAgeStatistics`, `getProductMix`, `getCountryAnomalies`, `getCountryClassification`, `getDataCoverage`, `similar` доступны у результата `createAnalytics(data)`.

Дубли проверяются по координатам, официальному имени и одинаковой мощности одного владельца в пределах 150 км либо при совпадающем названии комплекса перед тире. Кандидаты **не удаляются автоматически**: два объекта могут быть самостоятельными площадками. Примеры — Port Harcourt, Liaoyang, Baku, Paraguaná. Для Paraguaná две записи имеют одинаковую мощность комплекса и координаты примерно в 198 км друг от друга: требуется проверка и геометрии, и мощности. Суммы записей могут завышать мощность комплексов и не являются подтверждённой оценкой национальной отрасли. Полные списки: `public/data/quality.json`; интерфейс Data quality позволяет скачать JSON. Неодинаковые имена/координаты могут скрывать дополнительные дубли; ручная верификация источников — следующий этап.

Режим Fuel Prices реализован, но честно показывает No data. Все поля цен, единиц и дат в предоставленном наборе пусты. Он начнёт окрашивать карту, когда в исходниках появятся числа с датой и единицей; несовместимые единицы разделены селектором. Цены не подставляются из интернета.

## Подложки и доступность

По умолчанию **Atlas · clean**: локальные полигоны без внешних тайлов, спокойная карта с английскими подписями.

| Подложка                     | Источник и условия                                                                                                                      |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| OpenStreetMap                | `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, attribution OSM, [usage policy](https://operations.osmfoundation.org/policies/tiles/) |
| CARTO Positron / Dark Matter | `https://a.basemaps.cartocdn.com/light_nolabels/{z}/{x}/{y}.png` / `dark_nolabels`, attribution OSM+CARTO, **требуется ключ**           |
| Esri World Imagery           | `https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`, attribution Esri/поставщиков         |
| OpenTopoMap                  | `https://tile.opentopomap.org/{z}/{x}/{y}.png`, attribution OSM/SRTM/OpenTopoMap CC-BY-SA                                               |

Официальный [репозиторий CARTO](https://github.com/CartoDB/basemap-styles) теперь требует API key и отмечает вывод raster-сервиса из эксплуатации. Получить [ключ CARTO](https://carto.com/basemaps/apikey/), добавить в `oil stat/.env.local`:

```dotenv
VITE_CARTO_API_KEY=your_provider_key
```

Ключ frontend-подложки виден браузеру: ограничьте разрешённые домены у провайдера. Без ключа приложение явно сообщает об ограничении и оставляет локальную карту; оно не выдаёт локальную карту за успешно загруженную CARTO. Это единственное внешнее условие, необходимое для полноценного использования обоих CARTO-переключателей. Остальные подложки проверяются браузерным тестом на успешный HTTP 200 хотя бы одного тайла; доступность всех тайлов/масштабов не гарантируется провайдерами.

[Описание OpenTopoMap](https://services.opentopomap.org/about), [Esri World Imagery service](https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer). Тайлы не скачиваются массово, не проксируются и не кэшируются offline. Attribution видна на карте. Ошибка внешней подложки не должна отключать локальные аналитические слои. OSM/topo/satellite могут содержать собственные подписи, заложенные в растровые тайлы; чистый Atlas полностью управляет подписями.

## Проверка и дальнейшее развитие

`tests/analytics.test.mjs` проверяет missing/zero, десятичные разделители, возраст, конвертацию, неполную мощность, HHI, spatial join/holes/coastal ambiguity и conservation реальных агрегатов. `tests/browser.mjs` проверяет реальные rendered features, клики по карте, карточки, режимы, поиск, сравнение, владельца, подложки, URL, reset, zoom и узкий viewport. Ошибки JS и console error завершают тест с ошибкой; отменённые тайловые запросы при переключении слоя записываются отдельно.

Приоритеты развития: верифицировать дубли комплексов и владельцев; дополнить мощности/возраст/статусы; добавить согласованные годовые ряды, фактический throughput и активную мощность; наполнить цены с проверенными единицами/датами; подключить CARTO vector styles с ключом; добавить отдельную группировку parent companies и реальные доли участия. Для глобального production-сервиса полезны генерализованная геометрия, локализованные UI-подписи, серверная доставка с gzip/brotli и закреплённые лицензионные договоры подложек.
