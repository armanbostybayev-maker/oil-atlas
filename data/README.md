# Data pipeline

Обычные `npm ci`, `npm run dev`, `npm run build`, `npm test` используют готовые файлы из `public/data`. Python, Excel и внешняя GIS-директория для них не нужны. Обновление данных запускается только явно.

## Источники и приоритет

1. `data/sources/base.json` — версионируемый нормализованный снимок стран и НПЗ. При миграции он создан из текущего набора, без потери полей; это самостоятельный источник, а не ссылка на runtime-файл.
2. `data/sources/countries.geojson` — исходная геометрия этого снимка.
3. `data/sources/enrichment.json` — постоянные дополнения стран и явно импортированные реестры НПЗ. Дополнения применяются **после** базового снимка, включая импорт новой GIS-базы. Начальные country patches восстановлены сравнением текущего набора с резервной копией до импорта стран от 2026-09-16. Уже существующие значения также сохранены в baseline.
4. `data/archive/` — исторические резервные копии. Не участвуют в генерации и не публикуются. Не удалены, поскольку сохраняют происхождение миграции.

Поток: **источник → нормализация → постоянные дополнения → валидация → quality/duplicate checks → runtime**. Runtime: `public/data/atlas.json`, `countries.geojson`, `quality.json`, `manifest.json`. Не редактируйте их вручную. Аналитические агрегаты по-прежнему вычисляются `createAnalytics` при загрузке приложения.

`values`, `years`, `raw` дополнений объединяются по ключам; скалярные поля — по наличию ключа. Пустая Excel-ячейка не стирает известное числовое значение; 0 сохраняется. Исходные Excel-колонки остаются в `raw`. Для намеренного удаления значения внесите `null` в соответствующий patch и перегенерируйте. Удаление ключа patch возвращает приоритет базовому источнику.

Обновление НПЗ — отдельное явное действие: `--refineries` заменяет реестры **целых стран, представленных в листе**, как прежний Python importer. Остальные страны сохраняются. ID импортированных записей имеют вид `registry-<country-id>-<row-number>` и стабильны при неизменном порядке строк. Старые ссылки на заменённые НПЗ могут перестать работать. Мощность в барр./сут. сохраняется отдельно; при отсутствии мощности в т/год она не выдумывается. Неизвестная страна или некорректная схема останавливает весь импорт.

## Команды

```sh
# Полная воспроизводимая генерация из источников в репозитории:
npm run data:update

# Валидация без изменения источников и runtime:
npm run data:update -- --dry-run

# Изолированный предпросмотр. Не изменяет data/sources или public/data:
npm run data:update -- --out artifacts/data-preview

# Явная замена GIS-базы с сохранением всех постоянных дополнений:
npm run data:update -- --source /path/to/geojson --dry-run
npm run data:update -- --source /path/to/geojson

# Импорт стран: сначала просмотр, затем публикация:
npm run data:update -- --excel workbook.xlsx --dry-run
npm run data:update -- --excel workbook.xlsx

# Импорт стран + замена реестров представленных стран:
npm run data:update -- --excel workbook.xlsx --refineries --dry-run
npm run data:update -- --excel workbook.xlsx --refineries
```

GIS-директория должна содержать `country world.geojsonl` и `refinary world.geojsonl` в исходной схеме `normalize.mjs`, WGS84. QMD — только метаданные, для вычислений не нужны. Альтернатива CLI: `OIL_ATLAS_SOURCE`; эта переменная читается **только** командой обновления. После успешного GIS-импорта база и геометрия сохраняются в `data/sources`, поэтому последующая генерация больше не зависит от внешней папки. Несовпадение ID стран с постоянными дополнениями требует явного разрешения, а не молчаливого пропуска.

Excel требует Python 3 и `openpyxl` (`python -m pip install openpyxl`). Интерпретатор задаётся `--python <executable>` или `PYTHON`, иначе используется `py` на Windows / `python3` на остальных системах. Лист стран: `country_world_globalpetrolprice`; лист НПЗ: `НПЗ свежие реестры`. Все нормализация/merge/publication находятся в Node pipeline; Python только читает таблицы. Workbook не нужен для повторной генерации: импорт сохраняет его дополнения в JSON.

Совместимые старые entry points сохранены:

- `npm run preprocess -- ...` — alias `data:update`.
- `node scripts/update-from-excel.mjs workbook.xlsx ...` и `python scripts/update_from_excel.py workbook.xlsx ...` — импорт стран.
- `python scripts/update_refineries.py workbook.xlsx ...` — только реестры НПЗ, без импорта стран (`--refineries-only`).

## Запись и проверки

Все входы читаются, объединяются и проверяются до публикации. Пересчитываются spatial diagnostics, missing fields, конфликтующие статусы, дубли координат/имён и возможная общая мощность. При воспроизведении снимка пространственные назначения сохранены; spatial join повторяется при импорте GIS. Геометрия и ID стран должны совпадать. `quality.json` и `atlas.quality` генерируются из одного объекта. Manifest содержит SHA-256 входов без текущего времени, поэтому одинаковые входы дают одинаковые байты.

Writer lock предотвращает два одновременных обновления. Файлы сначала записываются рядом во временные файлы, затем заменяются через rename; при обычной I/O-ошибке уже заменённые файлы откатываются. Это **не транзакция файловой системы при отключении питания**: выполняйте публикацию/deploy после завершения команды. После аварийного завершения проверьте отсутствие работающего updater перед удалением `data/.update.lock`; затем повторите генерацию. Не запускайте build одновременно с обновлением.

`--dry-run` пишет только временный lock; `--out` не сохраняет импортированные источники. Ни ошибка чтения внешних данных, ни ошибка валидации не меняет runtime.

## Размер данных

Initial load читает оба файла параллельно: atlas ≈2.77 MB, геометрия ≈13.52 MB (в сумме ≈16.29 MB без сжатия; gzip ≈5.15 MB). Геометрия нужна сразу для карты; `raw` используется в карточках. Lazy loading геометрии отложит саму карту, поэтому здесь не внедрён. Резервные копии на ≈4.82 MB вынесены из public. Следующий безопасный эксплуатационный шаг — настроить gzip/Brotli для JSON на хостинге; последующая генерализация геометрии требует отдельной визуальной проверки островов и границ. Spatial join должен продолжать использовать полную геометрию.
