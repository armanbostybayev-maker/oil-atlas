# Нефтяные и нефтегазовые объекты

Источник — лист `Реестр` пользовательского файла `Мировой_реестр_нефтяных_месторождений.xlsx`. Импорт от 22 сентября 2026: **7 066 записей, 92 страны**. На карте — **6 491 объект** (89 стран): 5 497 с точными координатами, 994 с приблизительными. Ещё 575 записей без валидных координат сохранены для поиска и карточек.

## Обновление

Нужен Python 3, сторонние библиотеки не требуются:

```powershell
npm run data:oilfields -- "C:\путь\Мировой_реестр_нефтяных_месторождений.xlsx"
npm run test:oilfield-import
npm test
npm run lint
npm run build
```

Команды автоматически используют Python 3 из комплекта Codex Desktop либо PATH. Можно задать полный путь через `OIL_ATLAS_PYTHON`. Если Python отсутствует, команда сообщит об этом без изменения данных. Для предварительной проверки используйте `--output artifacts/oilfields-preview.json`. После проверки повторите импорт без `--output`.

Импортёр читает XLSX как ZIP/XML. Он находит лист по имени и строку заголовков, проверяет 37 колонок и уникальные ID, не изменяет книгу. Ошибочная схема или повтор ID прерывают импорт до публикации файла. Результат записывается атомарно в `public/data/oilfields.json`; содержит SHA-256 источника и диагностику. Пустые ячейки остаются `null`, числовой ноль сохраняется. Годы вроде `2025 (expected)` сохраняются строками; фильтр по годам использует явно указанный начальный четырёхзначный год. Дата не превращается в подтверждённый факт начала добычи.

## Архитектура

- Статический JSON хранит таблицу колонок и массивы значений. В браузере декодируется один раз, независимо от основной карты; Excel в браузер не передаётся. Подробности остаются в памяти приложения, в WebGL-worker уходят только координаты, ID и статус.
- `analytics/oilfields.mjs`: чистые функции фильтрации, проверки координат, аналитики и GeoJSON. Невалидные координаты исключаются из карты, но не из реестра.
- `map/OilfieldLayer.mjs`: GeoJSON source, кластеризация до zoom 13, чёрные SVG-качалки и морские платформы, выделенный symbol layer. Числа кластеров — локальные sprites без внешнего сервера шрифтов. Нет DOM-маркера на каждый объект.
- `controls/useOilfields.jsx`: отдельная загрузка с retry/abort, мемоизированные выборки, debounce области карты 180 мс, сохранение фильтров/слоёв/панели в `localStorage` (`oil-atlas-fields-v1`).
- `panels/OilfieldPanel.jsx`: фильтры с применением и сбросом, поиск с постраничным списком, карточки месторождения и танкера, диаграммы-кнопки. Клик на диаграмме включает/снимает соответствующий фильтр, не меняя остальные.
- Счётчики аналитики относятся к координатным объектам в текущих географических границах карты, а не к количеству нарисованных символов-кластеров. Панели поверх карты не вычитаются из географической области. Фильтр «только в текущей области» фиксирует границы на момент нажатия; «Снять ограничение области» удаляет их.
- На мобильных экранах используется нижняя сворачиваемая панель. Карточки и группы танкера доступны с клавиатуры, имеют `aria-expanded`/`aria-controls`; скрытые пользовательские секции исключены из навигации через `inert`. Анимация отключается при `prefers-reduced-motion`.

## Ограничения данных

Записи включают месторождения, активы, блоки, проекты, залежи и комплексы. Они не обязательно независимы. **Запасы и добыча не суммируются**: различаются классы, годы и единицы, возможны пересечения объектов. Счётчик наличия данных означает наличие исходного значения по нефти или газу, включая настоящий ноль.

Статусы UGS и exploration не заменяются другими: в карточке/фильтре остаются исходными категориями, все значки чёрные независимо от статуса. Исходные названия компаний, стран, классы запасов и единицы сохранены. Никакие отсутствующие значения не достраиваются.

## Проверки

`npm run test:oilfield-import` проверяет преобразование XLSX, нули/пропуски, координаты, повторные ID и детерминизм. `npm test` проверяет реальный реестр, фильтры, аналитику и границы через антимеридиан вместе с прежними тестами танкеров/НПЗ. `npm run lint` запускает ESLint для активных JS/JSX-модулей (резервные копии и сборки исключены).

Браузерные сценарии запускаются при работающем dev-сервере:

```powershell
npm run dev -- --port 5182
# В другом терминале:
npm run test:oilfields
```

Можно задать `OIL_ATLAS_TEST_URL`. Тест использует Edge/Playwright, реальный реестр и детерминированный тестовый ответ AIS. Результат и снимки desktop/mobile сохраняются в `artifacts/oilfields/`. Он проверяет кластер, выбор объектов, независимые карточки, клавиатуру, слои, фильтр области, диаграммы и сохранение настроек. Доступность внешнего AIS проверяется отдельно после публикации.

При переходе с широкого экрана на телефон список типов танкеров закрывается, чтобы не перекрыть нижнюю панель. Когда нижняя панель открыта, прежняя левая панель анализа скрыта; сворачивание возвращает её. Выбор страны/НПЗ или открытие прежнего меню на телефоне автоматически сворачивает нижнюю панель.

## Файлы этой доработки

Новые файлы:

- `scripts/import_oilfields.py`, `scripts/python.mjs` — импорт XLSX и выбор интерпретатора;
- `public/data/oilfields.json` — полный реестр и диагностика;
- `analytics/oilfields.mjs` — фильтры, GeoJSON и аналитика;
- `map/OilfieldLayer.mjs`, `map/oilfield-icon.mjs` — слой и SVG-иконка;
- `controls/useOilfields.jsx`, `controls/oilfields-ru.mjs` — состояние и перевод;
- `panels/OilfieldPanel.jsx`, `styles/oilfields.css` — правая панель и адаптивная компоновка;
- `tests/oilfields.test.mjs`, `tests/oilfields-browser.mjs`, `tests/test_oilfield_import.py` — проверки;
- `eslint.config.mjs` — конфигурация линтера;
- `data/OILFIELDS.md` — эта инструкция.

Обновлены `components/AtlasApp.jsx`, `map/WorldMap.jsx`, `map/TankerCard.mjs`, `panels/VesselTypes.jsx`, `controls/ru.mjs`, `controls/i18n.jsx`, `package.json`, `package-lock.json`, `README.md`. В `tests/ais.test.mjs` добавлены фигурные скобки у Promise executor для правила ESLint, логика теста не изменена. `dist/` пересобирается автоматически; исходные данные НПЗ и API танкеров этой доработкой не изменяются.

Map symbols: black pumpjacks on land and black offshore platforms outside land polygons. Classification is derived by scripts/classify-oilfields.mjs against data/sources/countries.geojson, retained separately in locationKinds; original registry cells are unchanged. It is approximate: coastline resolution, inaccurate coordinates and inland waters may affect results. Run the classifier after direct imports (npm run data:oilfields runs both steps). Clusters are black; status chart colours remain analytical only. A persistent Oilfields toggle is always visible above layer settings.
